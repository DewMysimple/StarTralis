# StarTralis / Astral Flow 第二轮迭代：消除周期性闪烁，建立连续稳定的星轨渲染

你现在负责修复现有的 React + Vite + TypeScript + Canvas 2D 星轨项目。

项目名称：StarTralis / Astral Flow。

这次任务不是从零重做。请保留现有的页面设计、交互方式、粒子运动模型和工程结构，在已有实现的基础上修复和优化。

## 一、当前已确认问题

用户提供的新版本录屏共 256 帧、24 FPS、约 10.67 秒。

逐帧亮度分析发现：

- 星轨每约 0.45 秒出现一次规律性亮度骤降。
- 4–9 秒的主要展示阶段，单次下降通常约为 12%–17%。
- 亮度随星轨积累而增加，但会周期性向下跳变，形成锯齿形波动。
- 肉眼看到的结果就是“一闪一闪”。

当前代码的 `StarTrailEngine.ts` 存在：

- `rebuildAt`
- `rebuildHistory(now)`
- 每隔 `.45` 秒重建历史星轨
- 先执行 `clearCanvas(ctx)`，然后通过历史样本和 `createConicGradient()` 重新绘制星轨

需要首先检查并验证：周期性重建前后的颜色、透明度和像素能量是否不一致。

这一机制是当前最主要的怀疑对象。不要在不检查真实源码的情况下直接假定所有问题都来自录屏设备。

## 二、第一优先级：消除周期性亮度骤降

不要简单地调低 brightness 或增加 glow。

不要通过 CSS opacity 动画掩盖周期性闪烁。

优先改造历史轨迹渲染：

1. 不再每隔固定时间清空并重建整个历史 Canvas。
2. 将粒子的历史位置、角度、时间戳和曝光度作为唯一的轨迹数据来源。
3. 设计统一的按时间计算的轨迹可见性和透明度衰减函数。
4. 在持续按压期间，使用同一套绘制规则连续生成可见轨迹。
5. 不允许正常增量绘制与周期性重建使用两套亮度结果不一致的模型。
6. 确保星头与最近一个历史采样点之间始终存在连续的连接。
7. 保留原有的轨迹寿命限制，避免长时间按压后形成永久完整圆环。
8. 保证按压超过 46 秒仍然稳定，不能产生无法消失的残留。

首选方案是有限历史驱动的确定性渲染。

如果每帧完整重新计算造成性能问题，可以进一步使用轨迹分段合批、缓存和其他性能优化方法。

不要直接用一个未经验证的双缓冲淡入淡出补丁来掩盖亮度差异。

## 三、释放状态的独立处理

当用户松开鼠标或手指：

1. 停止新增轨迹。
2. 冻结当前已经形成的完整星轨画面。
3. 使用单一连续的透明度曲线进行淡出。
4. 约 1.05 秒后恢复 Idle 状态。
5. 保留背景星点、标题、副标题和中心圆环。
6. 释放过程中再次按下时，不能出现轨迹突然跳跃或重新闪烁。

避免多个独立衰减系数在释放阶段叠加造成过快消失。

## 四、第二优先级：视觉质量优化

在闪烁修复后，再调整：

- 星轨密度，让星轨不再像过于密集的机械圆环。
- 长短弧线比例，让画面具有更自然的疏密变化。
- 星头与星尾的亮度关系，增强长曝光摄影感。
- 轨迹透明度，使大部分轨迹暗淡、少数轨迹突出。
- 线段连续性，减少明显的断续虚线。
- 冷白色与银灰色的明暗分层。

可以先测试桌面端 320–400 颗粒子，但最终数量要依据效果和实际帧率决定。

不要改变作品的核心构图、颜色方向和文字排版。

## 五、增加新的自动化稳定性测试

现有测试侧重于初始、长按和松开等固定时间点，不能充分发现周期性闪烁。

请扩展 Playwright 测试：

1. 在持续按压期间连续采样动态 Canvas。
2. 使用固定的测试分辨率和 DPR。
3. 记录时间戳、亮度或 Alpha 总量、帧耗时。
4. 绘制完整的亮度变化曲线。
5. 检查按压 3–8 秒期间是否存在周期性负向亮度跳变。
6. 检查 0.45 秒附近及其倍数处是否存在周期性异常。
7. 在排除开始激活和结束释放阶段后，将单帧动态轨迹总亮度下降不超过约 5% 作为初步验收目标，并结合实际渲染行为合理调整。
8. 测试持续 8 秒、20 秒、46 秒的长按表现。
9. 测试快速连续按压、失焦、取消、窗口缩放和高 DPR。

测量本身不得明显干扰动画运行。必要时使用低分辨率测试场景或离线截图分析。

请额外生成修复前后的亮度曲线对比、关键帧截图和实际性能测量记录。

不能仅因为 npm test 通过就宣布视觉问题修复。

## 六、性能要求

优先保证视觉稳定和运动连续性。

但必须继续关注：

- 单一 requestAnimationFrame。
- 基于 deltaTime 的运动更新。
- 不在 React State 中保存逐帧粒子数据。
- 限制粒子数量和历史容量。
- 缓存可复用的发光资源。
- 避免不必要的内存分配和垃圾回收。
- 保留合理的 DPR 上限。
- 低性能设备自动降低质量。
- 保持触屏和桌面兼容性。

对 60Hz 桌面环境，以尽可能接近稳定 60 FPS 为优化目标，不得通过破坏星轨连续性来换取帧率。
