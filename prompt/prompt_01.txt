# React + Vite 实时星轨交互视觉作品：Astral Flow

## 一、项目目标

你是一名具有丰富经验的 Creative Developer、Creative Technologist 和前端图形渲染工程师。

现在需要你在当前工作区中，开发一个名为 **Astral Flow** 的全屏交互式星轨视觉网页。

技术栈：

- React
- Vite
- TypeScript（如果现有工程使用 JavaScript，则沿用现有技术体系）
- HTML Canvas 2D API
- CSS

核心目标：

复刻参考视频中的真实星轨视觉效果。

这不是一个普通的星空背景动画，也不是一个简单的粒子特效。

我要的是：

**用户按住屏幕，星星开始围绕一个固定的天体中心运动，并逐渐留下真实、细腻、长短不一的圆弧形星轨；用户松开屏幕，所有已经形成的星轨在短时间内自然消散，最终恢复为最初安静的星空。**

整个作品应该像一个精致的数字艺术装置。

请直接在当前工程中完成开发，不要只提供设计方案或伪代码。

如果本地工程中存在参考视频，请分析视频关键帧。

如果没有本地视频文件，也不要停止任务，直接按照下面提供的视觉分析执行。

参考视频的关键特征：

- 视频分辨率：2956 × 1440。
- 帧率：30 FPS。
- 总时长：约 50.6 秒。
- 0 秒：只有稀疏背景星点、标题和中心定位圆环。
- 2 秒：出现许多短小的运动光迹。

- 12 秒：星轨仍然存在，展示文字发生变化。
- 46 秒：星轨达到非常丰富的状态。
- 48 秒：开始明显消散。
- 49 秒：基本恢复为最初的静态星空。

注意：这些时间点是参考视频的视觉阶段，不要求网页按照视频时间轴自动播放。

实际网页必须由用户的按压和松开行为控制。

# 三、最终视觉设计

## 1. 页面整体

创建一个全屏、无滚动条的深色星空场景。

视觉方向：

- 深蓝黑色背景。
- 接近真实长曝光摄影的星轨。
- 银白色光线为主。
- 少量冷蓝色星光作为点缀。
- 极其克制的辉光。
- 细腻、安静、神秘。
- 保持足够的暗部和留白。

背景颜色建议：

#05070D

可以使用少量 CSS radial-gradient 制造非常微弱的深蓝色空间层次。

增加轻微的边缘暗角，但不要让背景出现明显的渐变色块。

不要使用现成的星空背景图片。

不要使用预先录制的星轨视频。

所有星点和星轨必须由 Canvas 2D 实时生成。

## 2. 页面排版

严格控制页面元素。

页面只需要：

- 主标题。
- 副标题。
- 星空背景。
- 动态星轨。
- 一个固定的中心定位圆环。

不要添加导航栏、卡片、侧边栏、复杂按钮、功能面板、数据面板或其他无关 UI。

主标题：

Astral Flow

副标题：

Following the silent movement of distant stars.

排版要求：

- 标题使用优雅的衬线字体。
- 优先采用 Georgia、Palatino、Iowan Old Style 等本地字体回退体系。
- 标题颜色为柔和的白色。
- 副标题为低亮度灰色。
- 标题字号使用响应式 clamp。
- 标题与副标题保持适当间距。
- 不要使用粗重的无衬线科技字体。

参考排版：

标题水平居中，位于整个屏幕高度约 48%–51% 的位置。

副标题紧跟标题下方。

## 3. 星轨中心的位置

这是非常重要的构图要求。

不要把星轨中心直接放在页面正中央。

参考视频和截图中的星轨中心位于：

- 水平方向：约 50%。
- 垂直方向：约 66%–68%。

也就是说，星轨中心略微偏向屏幕下方。

而标题则处于中心偏上的位置。

这样可以让标题和星轨形成空间上的层次关系。

移动端可以根据屏幕比例将中心调整到 63%–66% 的高度。

## 4. 中心定位圆环

在星轨中心绘制一个非常细小的圆环。

要求：

- 直径约 26–30 CSS px。
- 边框约 1px。
- 颜色为低亮度银灰色。
- 透明度适中。
- 无填充。
- 不需要明显发光。
- 不随星轨消散。
- 不随鼠标位置移动。

这个圆环是整个星轨系统的视觉中心。

请让它始终存在。

# 四、核心技术：Canvas 2D 星轨粒子引擎

不要使用 Three.js。

本项目没有必要使用 3D 场景。

请建立独立的 Canvas 2D 实时渲染系统。

建议采用两个 Canvas 图层：

### Layer 1：Background Canvas

负责：

- 静态背景星点。
- 极其微弱的背景星光。
- 稀疏的星空空间感。

初始建议生成 160–220 个背景星点。

这些星点应当：

- 分布随机。
- 大部分非常小。
- 亮度较低。
- 少量星点略微明亮。
- 不要平均排列。
- 不要出现明显网格。

背景星点不应该受到星轨消散逻辑影响。

### Layer 2：Star Trail Canvas

负责：

- 动态星星。
- 星星运动。
- 星轨累积。
- 光线叠加。
- 星轨衰减。
- 松开后的整体消散。

这个 Canvas 必须保持透明背景，独立叠加在背景图层之上。

# 五、建立真正独立的星体运动系统

这是整个项目最重要的技术部分。

不要通过绘制大量静态圆环来伪造星轨。

不要让所有粒子围绕中心同步旋转。

不要让星星在屏幕上随机直线移动。

我要的是每颗星星都拥有独立的圆周运动参数。

建议定义粒子数据结构：

StarParticle：

- radius：轨道半径。
- angle：当前角度。
- angularVelocity：角速度。
- direction：运动方向。
- brightness：基础亮度。
- size：星体大小。
- color：星体颜色。
- previousX：上一帧 X 坐标。
- previousY：上一帧 Y 坐标。
- activationDelay：激活延迟。
- phase：亮度变化相位。
- glowFactor：辉光强度。

每颗星星必须具有独立的随机参数。

## 1. 极坐标运动

星星围绕固定的中心点运动。

使用：

x = centerX + radius * cos(angle)

y = centerY + radius * sin(angle)

每一帧根据真实时间间隔更新：

angle += angularVelocity * deltaTime

不要直接使用固定的每帧角度增量。

必须保证 60Hz、120Hz、144Hz 屏幕下，星体运动速度基本一致。

所有星星以同一主要旋转方向为主，但可以存在少量速度差异。

不要让所有粒子的运动轨迹完全一致。

## 2. 轨道半径分布

轨道半径不能平均分配得过于机械。

建议：

- 最小半径：约 35–45px。
- 最大半径：根据星轨中心到屏幕四角的最大距离动态计算。
- 外圈粒子可以略微多一些。
- 中心区域适当留白。
- 半径分布具有随机性。

让外圈轨迹自然延伸到屏幕边缘。

在宽屏、普通桌面、平板和手机上都应该自动适配。

## 3. 粒子数量

桌面端：

初始建议 420 颗动态星星。

允许根据设备性能调整到约 360–520 颗。

移动端：

初始建议 240–300 颗。

低性能设备应自动降低数量。

不要无限创建粒子。

## 4. 运动速度

建议每颗星星的角速度在一个合理范围内独立随机生成。

可以从约 0.12–0.42 rad/s 开始调试。

速度不能过快。

最终要形成一种缓慢、安静、持续的天体运动感。

可以有少量细微的速度差异，但不能让星轨显得杂乱。

## 5. 星轨的长短变化

这是复刻参考效果的关键。

每颗星星都必须具有自己的运动历史。

每一帧：

1. 更新星星的当前角度。
2. 计算新的 X、Y 坐标。
3. 连接上一帧位置和当前位置。
4. 绘制一段细小的弧形轨迹。
5. 更新上一帧的位置。

通过连续的运动线段逐渐形成圆弧。

不要直接绘制完整圆形。

不要让所有星轨的长度完全相同。

通过粒子速度、亮度、运动时间和画布衰减形成自然的长短变化。

建议使用：

- lineCap = round。
- 线宽约 0.55–1.2px。
- 少量特殊星体可以略微加粗。

必须保证线条细腻。

不要出现粗大的霓虹灯轨迹。

# 六、星星的视觉设计

将动态星星分成三种视觉层级。

### A. 普通星体

占主要数量。

特点：

- 很小的星头。
- 极细的白色弧形轨迹。
- 亮度较低。
- 不带明显辉光。

### B. 明亮星体

占少量。

特点：

- 比普通星体更明显。
- 星头有较高亮度。
- 尾部依旧细腻。
- 可以带一点淡蓝色。

### C. 特殊星体

只占极少数量。

特点：

- 星头更加明亮。
- 可以出现非常微弱的径向光晕。
- 轨迹略长。
- 亮度与普通星体形成层次。

颜色建议：

- 冷白色：主要颜色。
- 银灰色：低亮度轨迹。
- 极淡冰蓝色：少量特殊星体。

不要大面积使用蓝色。

不要使用紫色、粉色、彩虹色。

整体应当接近真实的夜空长曝光摄影。

## 星头与星尾

必须区分星星的头部和尾部。

星头：

- 亮度更高。
- 有清晰的小型光点。
- 极少数具有柔和辉光。

星尾：

- 细长。
- 亮度逐渐降低。
- 颜色以银白色为主。
- 不应具有明显的霓虹灯质感。

性能优化方面，不要对所有粒子每一帧都使用昂贵的 shadowBlur。

优先考虑缓存小型径向渐变辉光纹理，或者只对少数特殊星体绘制辉光。

# 七、星轨的累积与衰减

不要在每一帧都完全清空动态 Canvas。

需要使用 Canvas 持续累积历史运动轨迹。

推荐研究并使用：

globalCompositeOperation = "destination-out"

通过透明度控制逐渐擦除已有像素。

在按住期间：

- 只进行轻微的历史轨迹衰减。
- 新轨迹持续叠加。
- 较旧的轨迹逐渐变淡。
- 新生成的星头保持明亮。

建议使用基于 deltaTime 的指数衰减，而不是固定的每帧透明度。

这样才能避免不同屏幕刷新率下轨迹寿命不同。

在绘制新轨迹时，可以谨慎使用：

globalCompositeOperation = "lighter"

使部分重叠的星轨呈现自然的亮度叠加。

但必须控制曝光，不能把整个画面变成一片白色。

注意：

destination-out 只能用于动态星轨图层。

绝对不能让背景星点、标题和中心定位圆环一起消失。

# 八、用户交互系统

整个页面的交互逻辑必须简单自然。

用户可以在屏幕任意位置按住。

不需要把鼠标移动到中心圆环。

不需要点击额外按钮。

不需要拖动星星。

## 状态一：Idle

初始状态。

显示：

- 深蓝黑色背景。
- 稀疏背景星点。
- Astral Flow 标题。
- 英文副标题。
- 中心定位圆环。

此时动态星轨 Canvas 为空。

## 状态二：Pressing

用户按下鼠标或触摸屏幕。

立即启动星体运动。

但不要在第一帧就出现完整圆环。

需要有一个非常短的平滑启动过程，约 0.25–0.4 秒。

随着按压持续：

- 更多星星逐渐激活。
- 短小的轨迹开始出现。
- 轨迹逐渐延长。
- 圆弧逐渐增多。
- 星轨密度逐渐提高。

建议让粒子的激活时间在最初约 2–3 秒内分批展开。

用户持续按住约 6–8 秒时，应当逐渐形成参考视频中非常丰富的星轨效果。

不要让所有粒子在同一瞬间全部激活。

## 状态三：Releasing

用户松开鼠标或手指。

这是一个非常重要的交互阶段。

松开后：

1. 立即停止生成新的星轨线段。
2. 不再继续延长旧轨迹。
3. 已有星轨开始快速变暗。
4. 星头与尾部一起逐渐消失。
5. 约 0.8–1.2 秒后，恢复初始静态星空。

建议通过提高 destination-out 的擦除速度来实现。

不要使用简单的 display:none。

不要瞬间清空 Canvas。

不要让整个页面闪烁。

不要让标题和中心圆环跟随消失。

## 状态四：再次按下

当用户再次按住屏幕：

立即恢复星体运动。

如果上一次的星轨尚未完全消散，可以自然地恢复叠加。

不要出现粒子位置突然跳跃的情况。

必须重新同步粒子的上一帧坐标。

# 十、Canvas 高清适配与性能

这部分不能忽略。

## 1. devicePixelRatio

使用 window.devicePixelRatio 适配 Retina 和高分辨率屏幕。

但不要不加限制地使用极高 DPR。

建议根据设备性能设置合理上限。

Canvas 的实际宽高需要乘以 DPR。

绘图坐标仍然使用 CSS 像素。

每次调整尺寸后使用 setTransform 重新设置坐标变换，避免缩放累积。

## 2. ResizeObserver

使用 ResizeObserver 监听场景尺寸变化。

当浏览器窗口尺寸变化时：

- 更新 Canvas 尺寸。
- 更新星轨中心。
- 更新最大轨道半径。
- 重新绘制背景星点。
- 避免旧轨迹被拉伸变形。

## 3. requestAnimationFrame

使用 requestAnimationFrame 建立唯一的动画循环。

必须使用时间戳计算 deltaTime。

当页面切换到后台时暂停不必要的动画计算。

页面重新显示时，重新初始化时间戳，避免星星突然跳跃。

动画结束且所有星轨完全消散后，可以停止动态渲染循环。

## 4. React 生命周期

使用 useRef 保存：

- Canvas DOM。
- Canvas Context。
- 粒子数组。
- 当前交互状态。
- 动画帧 ID。
- 上一帧时间戳。

使用 useEffect 负责初始化、事件注册和清理。

组件卸载时必须：

- cancelAnimationFrame。
- 移除事件监听器。
- disconnect ResizeObserver。
- 清理必要的资源。

不要把每一帧的粒子位置放进 React State。

不要让 React 因为每一帧的 Canvas 绘制而不断重新渲染。

## 5. 其他性能要求

- 尽量批量绘制线段。
- 减少不必要的 Canvas 状态切换。
- 避免每帧创建大量临时对象。
- 不要频繁创建径向渐变。
- 避免每颗星星都使用 shadowBlur。
- 合理控制动态粒子数量。
- 考虑 prefers-reduced-motion。
- 不要为了追求效果造成明显的 CPU 占用。

# 十二、视觉调优标准

完成基础代码后，不要立即结束。

必须进行视觉调优。

重点检查以下问题：

### 问题一：是否像真实星轨？

如果看起来像雷达、科技圆环、旋转仪表盘，需要重新调整。

我要的是：

- 长短不一的圆弧。
- 细小的星头。
- 真实的光迹累积。
- 不规则的亮度分布。
- 自然的轨道密度。

### 问题二：是否有明显的中心区域？

中心不能被过多粒子填满。

外圈可以丰富，中心附近应该相对安静。

### 问题三：是否有真实的光感？

不要使用大面积蓝色光晕。

不要使用夸张的 Bloom。

星头亮度高于星尾即可。

### 问题四：是否保留足够留白？

标题不能被星轨完全遮挡。

标题、副标题和星轨中心之间需要保持清晰的空间关系。

不要增加多余 UI。
