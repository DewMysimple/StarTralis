# 已知问题

## 未解决问题与影响

本轮确认并修复了周期闪烁：旧版增量绘制与每 0.45 秒整幅重建的亮度不等价。固定时序 3–8 秒最大单帧下降从 16.91% 降至约 0.47%，12–20 / 36–46 秒约 0.50% / 0.46%；三个窗口均无超过 5% 的骤降。16 项浏览器用例通过，目前没有已确认且未修复的功能缺陷。

验证缺口与缺陷分开处理：

| 范围 | 已有证据与实际缺口 | 核实方法 |
| --- | --- | --- |
| 实物手机、Safari、Firefox | 目前为 Windows 无头 Chromium 156、CDP 触摸与 DPR 模拟；未验证其他浏览器及设备。 | 在目标设备检查按住 8 秒、松开、移出/取消、切后台、横竖屏，核对背景保留和无残轨。 |
| 设备性能 | 已有本机 1440×900 原生时间 46 秒、回调 P95 3.6 ms 记录；宿主 RAF 约 180 Hz。60/120/144 Hz 的对应检查仍是受控时间步进。 | 在目标硬件实测持续按压的帧间隔、温度和后台恢复；不能把回调时间等同完整 GPU 呈现，或声称物理 60 Hz 屏幕已验收。 |
| 云端发布 | 只有本地 dev 与 production preview 记录，没有托管部署。 | 获得具体发布需求后再验证构建路径、静态托管和真实 URL。 |

历史环境遗留：上一轮录制曾因 URL 空格编码，在项目外 `E:/Software%20Development/ArtTest/StarTralis/docs/verification` 生成截图与录像，清理被自动审批策略拒绝。正确交付已在本项目重建；本轮未复查或清理外部目录，不将其作为有效交付来源。[来源：验收记录]

## 复现与临时处理

分数 DPR 的冻结复制已改为 backing-store 坐标一比一，避免 CSS 宽高取整引起的重采样。演示录像使用 PNG 合成器帧与录制后 VP9 无损 RGB 编码，需完整 FFmpeg。默认有损录像曾测得约 5.98% 波动，同次直接 Canvas 仅 0.73%；录制诊断、页面渲染稳定性和独立原生性能分开，详见本轮摘要。

业务复验入口为 `npm test`；详细用例在 [starfield.spec.ts](../../tests/starfield.spec.ts)。录制入口为 `npm run capture:preview`，先启动 5180 开发服务器。脚本已使用 `fileURLToPath`，不要再用 `URL.pathname` 手工处理含空格的 Windows 路径。

闪烁回归见 [stability.spec.ts](../../tests/stability.spec.ts)。`node scripts/measure-stability.mjs before` 从 Git 固定提取旧版，不覆盖当前源码；新方案每帧按同一模型渲染。测试输入/读像素比较必须在 `clock.pauseAt` 后用 `runFor` 精确推进，避免测量本身造成虚假的续按下降。连续测量应同时覆盖全窗口与旧版实际重建帧，不能只对齐零相位 0.45 秒倍数。

已修复的高 DPR 边缘残留由 `clearCanvas()` 在真实 backing-store 坐标全量清理；若再次出现，可用 390×844、设备 DPR=3，按住后释放 1.15 秒，检查动态 Canvas alpha 是否完全归零。旧修复是排查线索，不作为当前未解决 bug。

5180 与 4173 均为 `strictPort`；若被其他进程占用，先核实进程归属，不直接终止无关服务。更改端口时同步 Vite、Playwright baseURL/webServer、录制脚本和运行说明。

## 证据与未核实项

2026-10-31，本轮 `npm run build` 和完整 16 项浏览器测试通过；验证对象为 `1b1db04` 加本轮本地修改。[本轮摘要](../../docs/verification/iteration-02/summary.json)与[机器测试报告](../../docs/verification/iteration-02/browser-tests.json)保存当前结果；初版 10 项固定时点测试曾遗漏周期闪烁，不再据此推断时间稳定性。

本轮原生 46 秒记录释放后为 `idle`、`alpha=0`、`errors=[]`；高 DPR 144 Hz 连续窗口最大下降约 0.35%，六次快速续按最大变化约 2.35%。以上只覆盖相应测试环境。项目外录制遗留仍只依据历史记录，当前存在性未核实，不阻塞本仓库版本管理。
